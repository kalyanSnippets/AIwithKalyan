My real prompt · 46 lines
Using what you learned from the REA analysis of this Wekan demo board: https://boards.wekan.team/b/D2SzJKZDS4Z48yeQH/wekan-r-open-source-kanban-board-with-mit-license Build a faithful clone of its board screen in this folder. Name it "REA Board". Match the layout, colours, fonts, spacing and behaviour as closely as you can. Do not use Wekan's name, logo or images, and write your own sample text and artwork. STACK React 19 + Vite, no UI library, plain CSS, native HTML5 drag and drop, state in one reducer file, everything saved in localStorage. MEASURE FIRST, DON'T GUESS Open the live demo and measure: page and header colours, font family and sizes, list width and gap, list header style, card radius, shadow and padding, label colour palette, badge colours, avatar size. Put them in one CSS variables block and use them everywhere. BOARD SCREEN - Top bar with the board title, a board menu area and member avatars. - Horizontal row of lists that scrolls sideways. An "Add list" control at the end. - Lists: title, card count, a WIP limit shown like (4/3) with the count in red when over the limit, a menu to rename, collapse and delete. Collapsed lists show as thin vertical strips. - Cards (minicards): auto ID (RB-1, RB-2...), title, several coloured labels, four date badges (received, start, due, end) where due turns red when overdue, a cover image drawn with CSS, member avatars (4 sample people), and a checklist badge with a percentage and progress bar. - "Add card" at the bottom of each list. CARD DETAIL PANEL (opens when a card is clicked) Edit title and description, labels (multiple), all four dates, members, cover colour, and checklists where items tick from the card itself. INTERACTIONS - Drag cards between lists and reorder inside a list, with a visible drop position. Handle both dragenter and dragover so real mouse drags work, and keep the layout stable while dragging. - Drag lists to reorder them. - Add, rename, delete lists and cards. Pressing Escape while typing must not lose the edit (blur the field first so it commits). - Refresh keeps everything. DATA Ship my own sample board with about 4 lists and 8 cards. Add an "Add sample lists" button that only APPENDS the sample lists. Never overwrite saved data, and migrate old saved data to any new format. TESTING Run the dev server, then in a real browser use real mouse drags (not only scripted events) to test every feature. Tick an item only if you saw it work. Back up localStorage before testing and restore it afterwards. Then show a side-by-side screenshot of the original and mine, list the 5 biggest remaining differences, and fix the top 2. Now, why does this prompt work? Four things, okay? One. "Measure first, don't guess." Claude opens the real app, and takes real numbers. Not "looks like blue". The exact colour code. Two. The stack is fixed. React, Vite, plain CSS. No random libraries. Three. I describe every part of the screen. Lists, cards, the card panel, drag and drop. And four... my favourite. Testing. I told Claude, "Tick an item only if you SAW it work." Why? Because AI loves to say "done", right? So we make it prove it. Okay, I press Enter. And now... we wait.
